RSS 2025 · NVIDIA / UCSD

NaVILA: a vision-language model that drives a legged robot

You give it a navigation instruction and the robot's recent camera frames. It answers with the next move in plain English, such as The next action is turn left 30 degree. A separate low-level locomotion policy turns that move into leg motion.

Llama-3 8BLanguage model backbone
SigLIP 384pxVision encoder (so400m, patch 14)
8 frames7 history + 1 current per step
4 actionsstop · forward · left · right

The two-level idea

This repository contains the high level only: the VLA model, its training code, and a simulator benchmark. The low-level locomotion policy lives in a separate repo (legged-loco), and the Isaac Sim benchmark in NaVILA-Bench.

flowchart LR
  I["Instruction text"] --> V
  C["Camera frames"] --> V
  V["NaVILA VLA
(this repo)"] -- "'move forward 75 cm'" --> L["Locomotion policy
(legged-loco repo)"]
  L -- "joint commands" --> R["Legged robot / simulator"]
  R -- "new frame" --> C

The VLA runs slowly and reasons in language. The locomotion policy runs in real time and handles obstacle avoidance.

Heritage matters. The llava/ package is a fork of NVIDIA's VILA codebase, which itself forks LLaVA. Most of its ~200 files support generic image/video chat models. NaVILA adds a small, focused layer on top: a VLN-CE dataset class, a navigation prompt, a Habitat trainer, and action parsing. Learn those parts first and treat the rest as library code.

Start here

Three ways to run it

Everything in the repo serves one of three workflows. They use different Python environments because the simulator pins old library versions.

Quick inference

env: navila · 1 GPU, 16 GB OK in 4-bit

Load the checkpoint, feed 8 frames plus an instruction, print the predicted action. Fastest way to see the model work.

python scripts/inference/quick_infer.py --num-samples 10

Training (SFT)

env: navila · multi-node, 8×GPU, DeepSpeed ZeRO-3

Fine-tune the pretrained VILA checkpoint on a mixture of navigation and video-QA datasets.

bash scripts/train/sft_8frames.sh

Simulator evaluation

env: navila-eval · Habitat 0.1.7

Run the model closed-loop in Matterport3D scenes on R2R / RxR val-unseen and compute SR, SPL, nDTW.

cd evaluation && bash scripts/eval/r2r.sh CKPT 1 0 "0"

# training / inference env

Follow one sample

Data flow

1. A training sample on disk

Each entry in annotations.json is one decision point inside one episode. This is the first RxR entry on this machine (frames list shortened):

{
  "video_id": "23289-31",
  "q": "We are going to start facing a living room area, and a kitchen island. Turn a slightly to the right, ...",
  "a": "The next action is turn right 15 degree.",
  "frames": ["23289/frame_0.jpg", "23289/frame_1.jpg", ... 72 paths]
}

frames holds every frame seen so far in the episode. The last one is the current view.

2. From frames to model input

  1. Sample 8 frames. vlnce_frame_sampling() keeps the latest frame and picks 7 evenly spaced history frames. Short histories are left-padded with black frames.
  2. Build the prompt. The instruction is cleaned (newlines removed, sentences capitalised) and inserted into a fixed template with 7 history <image> slots and 1 current slot.
  3. Apply the chat template. conv_templates["llama_3"] wraps it as a user turn. In training, the answer becomes the assistant turn and only its tokens are scored by the loss.
  4. Tokenize. tokenizer_image_token() turns each <image> into the placeholder id -200.
  5. Encode images. process_images() resizes to 384×384; vision tower plus projector give 196 embeddings per frame.
  6. Splice. prepare_inputs_labels_for_multimodal() swaps each -200 for its frame's embeddings and feeds the result to Llama-3.

The prompt is a contract. The same sentence ("Imagine you are a robot programmed for navigation tasks…") is copied into four places: llava/data/dataset.py, evaluation/vlnce_baselines/navila_trainer.py, llava/eval/run_navigation.py and scripts/inference/quick_infer.py. If you change it in one place, change it in all four, or train/test behaviour will drift apart.

3. Output grammar and how it becomes motion

The model always answers with one sentence. In simulation, navila_trainer.py parses it with regexes and breaks it into Habitat's fixed steps (25 cm forward, 15° turn):

… move forward 75 cm.
3 × MOVE_FORWARD (25 cm each). Values off the 25 grid snap to 25 / 50 / 75.
… turn left 30 degree.
2 × TURN_LEFT (15° each). Off-grid values snap to 15 / 30 / 45.
… turn right 45 degree.
3 × TURN_RIGHT.
… stop.
STOP ends the episode; metrics are recorded.

The first primitive runs immediately. The rest go into queue_actions and are executed on later loop turns without calling the model again. If nothing matches, the action defaults to forward 25 cm.

4. Results

Each episode's Habitat measures (distance to goal, success, SPL, nDTW, path length, oracle success, steps) go into eval_out/<ckpt>/VLN-CE-v1/val_unseen/val_unseen_<N>-<i>.json. Videos go to videos/ next to it when VIDEO_OPTION is set. eval_jsons.py averages across chunks.

Interfaces

API endpoints

NaVILA has no HTTP API. There is no server, route or endpoint in this repo. fastapi, uvicorn and gradio appear in pyproject.toml only because they were inherited from VILA, and no NaVILA code imports them. The interfaces you will actually program against are the Python functions, CLI arguments, config keys and registries below. If you need a network endpoint for a robot, you would wrap predict() from quick_infer.py in a small server yourself.

Save yourself an afternoon

Gotchas

SymptomCause and fix
Odd errors inside transformersSetup copies llava/train/transformers_replace/* over the installed transformers==4.37.2. Reinstalling transformers removes the patch; copy it again.
4-bit load fails with fp16_statisticsThe patched modeling_utils.py uses an old keyword. quick_infer.py wraps set_module_quantized_tensor_to_device to translate it. Reuse that shim in new scripts.
Training can't find dataEvery path in datasets_mixture.py starts with /PATH_TO_DATA. Replace them before training.
Eval "skipping -- evaluation exists"The trainer skips a chunk if its result JSON already exists. Delete the file to rerun.
webdataset import errorsThe package pins 0.2.86; VLN-CE needs 0.1.103. That is why eval uses its own env.
NumPy errors in habitat-simRun evaluation/scripts/habitat_sim_autofix.py from the repo root.
Eval must be launched from evaluation/Config paths like habitat_extensions/config/… and data/datasets/… are relative to that folder.
Out of memory on a 16 GB GPUUse --precision 4bit. Only the LLM is quantized; the vision tower and projector stay in fp16.
Model's checkpoint is bf16 but loads as fp16load_pretrained_model forces torch.float16 unless 4/8-bit is chosen. This is expected.
Changed the prompt and accuracy droppedSee the "prompt is a contract" note in Data flow.

Suggested first week

  1. Run quick_infer.py --num-samples 10 and read its output next to annotations.json.
  2. Read quick_infer.py top to bottom (≈200 lines). It is the shortest complete path through the model.
  3. Read LazyVLNCEDataset.__getitem__ in llava/data/dataset.py and compare its prompt with the one in quick_infer.py.
  4. Read NaVILATrainer._eval_checkpoint to see the closed loop and action parsing.
  5. Skim llava_arch.py up to prepare_inputs_labels_for_multimodal to understand the image splice.
  6. Only then set up the Habitat environment and run a short eval with EVAL.EPISODE_COUNT 20.

Terms of art

Glossary

VLA
Vision-Language-Action model: takes images and text, outputs an action.
VLN-CE
Vision-and-Language Navigation in Continuous Environments. The agent moves freely in a 3D scene instead of hopping between graph nodes.
R2R
Room-to-Room: English instructions over Matterport3D houses.
RxR
Room-across-Room: longer, more detailed instructions in English, Hindi and Telugu.
EnvDrop
Augmented R2R episodes; NaVILA ships annotations only, videos must be rendered.
Human
YouTube walking-tour videos labelled with actions, used to teach real-world motion.
ScanQA
3D scene question answering, mixed in to keep spatial understanding.
Habitat
Meta's 3D simulator. This repo pins habitat-sim and habitat-lab 0.1.7.
MP3D
Matterport3D, the scanned houses used as evaluation scenes.
SR
Success rate: the agent stops within 3 m of the goal.
OSR
Oracle success: the agent passed within 3 m at any point.
SPL
Success weighted by path length; penalises wandering.
nDTW
Normalised dynamic time warping: how closely the path follows the reference path.
val_unseen
Evaluation split with houses never seen in training.
ZeRO-3
DeepSpeed mode that shards parameters, gradients and optimizer state across GPUs.
